### 4.2 col-resize 회귀 위험 (★최대 위험, tasks.json P3-04 done_criteria 명시)

- **계약**: log-pane 표는 `<table>/<colgroup>/<thead>`를 **한 번만** 만들고 이후 **tbody innerHTML만 교체**한다. col-resize(`render/col-resize.js#initColResize`, col-resize.js:5)가 보존한 컬럼 너비가 tbody 교체로 초기화되지 않게 하기 위함. 근거: turn-views.js:391-419(renderLogPane "thead/colgroup 미변경"), turn-views.js:1001-1023(골격 멱등 주입), 1023(`initColResize` 골격 1회 부착).
- **React 회귀 위험**: JSX가 매 리렌더에서 `<table>`/`<colgroup>`을 재생성하면 사용자가 드래그한 컬럼 너비가 매번 리셋 — 현재 코드가 멱등 주입으로 막아둔 회귀가 부활한다.
- **가드**:
  1. `<TurnLogTable>`의 `<colgroup>`/`<thead>`를 **안정 노드로 유지** — `key` 안정 + tbody만 rows로 갱신. React 재조정이 colgroup `<col style="width:…">`을 건드리지 않도록 col 너비는 DOM(또는 col-resize ref)이 소유, JSX 인라인 style로 매 렌더 덮어쓰지 않음.
  2. col-resize를 `useRef(table)` + `useEffect(mount 1회)` 로 부착 — 현재 "골격 1회 부착"(turn-views.js:1023)과 동일 시맨틱.
  3. **수동 verify 보강(Gap)**: 컬럼 드래그 → 활성턴 전환/SSE 도착 후 너비 유지 확인. 단위테스트 불충분 → before/after 스크린샷 증거(P3-01의 resize verify 패턴 준용, tasks.json P3-01 test_strategy).
- **expand 복원도 동반 위험**: 현재 tbody 교체 전 펼침 id 캡처→복원(turn-views.js:399-418). React expand-state를 store/로컬로 올리면 tbody 재생성과 무관하게 펼침 유지 → 캡처 로직 자체가 불필요해지나, **이식 중간 단계에서 expand state를 먼저 올리지 않고 tbody만 JSX화하면 SSE 갱신 시 펼침이 닫히는 회귀** 발생. expand state 이관을 tbody JSX화보다 **선행**.

ESM은 hoisting으로 런타임 깨지지 않지만, React 분해 시 양쪽을 동시에 건드리면 import 데드락 위험.

**가드**:
1. `applyBloatedSysHeader`(헤더 뱃지)를 **store action으로 추상화** — turn-views(P3-06)도 detail-view(P3-07)도 store를 통해 헤더를 갱신 → 직접 import 제거 → 순환 소멸.
2. `updateSessionBadges`(turn-views.js:839)의 bloated-sys 재부착(turn-views.js:857-858)을 detail-view의 헤더 책임으로 합쳐 `<SessionBadges>` 단일 컴포넌트로 — 두 파일에 흩어진 detailBadges 갱신(turn-views.js:855, detail-view.js:144-176)을 SSoT화.
3. P3-06 착수 시 이 어댑터(임시 store action)를 **먼저** 두어야 P3-07 이전에도 컴파일 가능.

**llm-input-view / system-prompt-library 결합**: `openLlmInputForTurn`(turn-views.js:631)·setDetailView('llm'/'syslib')(turn-views.js:594-595)이 탭 전환 부수효과로 lazy 로드를 호출. React에선 탭 라우팅 store → 각 탭 컴포넌트가 자기 데이터를 `useEffect`로 로드(턴뷰가 직접 호출 제거).

## 7. facade 폐기 종료조건

루트 `session-detail.js` + `session-detail/index.js` 이중 facade의 **삭제 가능 시점**:

1. **외부 소비처 전환 완료**: 현재 import는 `main.js:26`, `views/detail-view.js:12`(둘 다 루트 facade). main.js가 React Router로 대체(P3-11/마지막)되고 detail-view가 `<DetailView>` TSX(P3-07)로 전환되면 facade import 0.
2. **호환 stub 제거**: `toggleTurn`/`toggleCardExpand`/`setTurnViewMode`/`renderTurnView`(turn-views.js:607-643)는 main.js의 레거시 위임(`[data-toggle-turn]`/`[data-toggle-card]`, main.js:810,827) 호환용 thin adapter. main.js 위임이 React onClick으로 이관되면 stub 폐기 → index.js의 re-export(index.js:37-41)에서 제거.
3. **subfile 직접 import 정리**: `main.js:44`의 `system-reminder-popover.js` 직접 import는 P3-07에서 `useSystemReminderPopover`로 흡수.
4. **검증**: `grep -rn "session-detail" packages/web/{src,assets} --include='*.{js,ts,tsx}'` → 코드 import 0 (주석 제외). 종료조건 충족 시 `session-detail.js` + `session-detail/{index,flat-view,turn-views,turn-rows,state}.js` 삭제. system-reminder.js는 lib로 이동, system-reminder-popover.js는 훅으로 흡수.

**종료조건 요약**: facade는 P3-05/06/07이 모든 export를 TSX/lib/store로 옮기고, main.js(P3-11)가 위임을 React로 대체한 뒤 삭제. 즉 **P3-04~07 단독으로는 facade를 못 지운다** — main.js 라우터화(P3-11)가 마지막 트리거.
