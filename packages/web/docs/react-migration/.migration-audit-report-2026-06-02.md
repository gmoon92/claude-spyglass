## 3. "리액트답게" 재설계 여부 — 상세 분석

### ✅ 잘 된 부분 (React-way 적용)

#### 3.1 선언적 라우팅 (React Router v6)
- **원본**: `main.js`의 `applyAppMode` — `body[data-app-mode]` 속성 토글 + 수동 DOM show/hide
- **전환 후**: `BrowserRouter` + `Routes`/`Route` + `useLocation`/`useNavigate`
- **품질**: `AppModeSync` 컴포넌트가 URL↔store 양방향 동기화를 선언적으로 처리. 딥링크/뒤로가기 정합성 보장. `useRef`로 초기 마운트 시 클로버링 방지.
- **평가**: ⭐⭐⭐⭐⭐ **우수** — 단순 포팅이 아닌 선언적 패러다임 전환

#### 3.2 상태 관리 (Zustand)
- **원본**: `assets/js/state.js` — 모듈 레벨 `let` 변수 + getter/setter
- **전환 후**: `zustand` + `persist` 미들웨어. `localStorage` 영속은 어댑터 패턴으로 레거시 바이트 호환 유지.
- **품질**: selector 기반 구독으로 불필요한 리렌더 방지. `partialize`로 영속 대상을 `activeRange`만 제한.
- **평가**: ⭐⭐⭐⭐⭐ **우수** — 전역 변수 SSoT를 현대적 상태 관리로 재설계

#### 3.3 SSE 연결 (useSSE 훅)
- **원본**: `assets/js/sse.js` — 모듈 싱글톤 `_source`, `_retryTimer`, `_callbacks`
- **전환 후**: `createSSEController` 클로저 캡슐화 + `useSSE` React 훅. 마운트별 독립 인스턴스 + 언마운트 시 `stop()` cleanup.
- **품질**: Zod 검증(`parseSSEMessage`)으로 런타임 안정성 향상. `useRef`로 콜백 신원 안정화 → 불필요한 재연결 방지.
- **평가**: ⭐⭐⭐⭐⭐ **우수** — React 생명주기에 맞는 캡슐화 + 타입 안정성

#### 3.4 컴포넌트 아키텍처 (Feature-based)
```
src/
├── app/          # 라우팅·셸·레이아웃
├── features/     # 도메인별 기능 (dashboard, session-detail, meta-docs, settings...)
├── components/   # 공용 UI (design-system/, render/, primitives/)
├── hooks/        # 공용 훅 (use-sse, use-tooltip, use-chart-reveal)
├── stores/       # Zustand 스토어
├── lib/          # 퓨어 유틸
└── schema/       # Zod 런타임 스키마
```
- **평가**: ⭐⭐⭐⭐⭐ **우수** — Feature Slices + 단방향 의존성(`app → features → hooks/stores/components`)

#### 3.5 선언적 부수효과 (AppShell)
- `useEffect`로 `body[data-app-mode]` 동기화, `⌘B` 단축키, `useTooltip()` 전역 위임 등을 선언적으로 처리.
- SSR 안전: 모든 DOM 접근은 `useEffect` 낸부.

---

### ⚠️ 보통 수준 (개선 여지 있음)

#### 3.6 CSS-in-JS 미도입
- 여전히 **24개의 외부 CSS 파일**(`assets/css/*.css`)을 데몬이 서빙하고, Vite는 이를 번들에 포함하지 않음(`externalizeDaemonAssets` 플러그인).
- 컴포넌트와 스타일이 물리적으로 분리되어 있어 **co-location 부재**.
- **제안**: 디자인 시스템 primitives에는 CSS Modules 또는 Tailwind 도입 검토.

#### 3.7 i18n 미전환
- `window.I18n` 전역 객체(바닐라 IIFE)를 여전히 사용. React 진입 전 `<script>`로 로드.
- React 컴포넌트는 `tt()` 함수로 문자열을 조회.
- **제안**: `react-i18next` 또는 ICU 기반 React i18n 라이브러리로 전환 시 컴포넌트 수준 lazy loading 가능.

#### 3.8 테스트 실패 30건
- 1,252개 중 30개(2.4%) 실패. CI 게이트가 없다면 회귀 위험.
- **제안**: 실패 테스트를 `skip` 처리하거나 즉시 수정하여 **0 fail** 유지.

---

### ❌ 리스크 있는 부분 (리액트답지 않은 잔여물)

#### 3.9 DOM 직접 조작 잔여
```tsx
// AppShell.tsx
useEffect(() => {
  const body = document?.body;
  if (!body) return;
  body.dataset.appMode = activeMode;  // body[data-app-mode] 직접 조작
}, [activeMode]);
```
- **의도적**: 레거시 CSS(`body[data-app-mode]` 셸렉터)와의 병존을 위해 불가피.
- **리스크**: React 외부 DOM과 동기화 지점. 향후 CSS가 CSS Modules로 전환되면 제거 가능.

#### 3.10 `requestAnimationFrame` 트릭
```tsx
// main.tsx
requestAnimationFrame(() =>
  requestAnimationFrame(() => document.documentElement.classList.add('app-ready'))
);
```
- 원본 `main.js`의 레이아웃 활성화 타이밍을 그대로 이식.
- React 마운트 완료 시점을 보장하지 않는 hacky한 방법. `useLayoutEffect` 또는 CSS `&:has(#react-root)`로 대체 가능.

#### 3.11 일부 "뷰/컨테이너" 분리 미흡
- Settings 패널(`DiagPanel`, `GraphPanel` 등)은 `*Panel.tsx`(컨테이너)와 `*PanelView.tsx`(프레젠테이션)로 분리되어 있으나, 컨테이너 쪽 커버리지가 0~5%로 **테스트가 거의 없음**.
- 이는 사실상 "뷰만 테스트하고 데이터 흐름은 검증하지 않음" 상태.

## 6. 결론

본 마이그레이션은 **"리액트 문법만 얹은 것"이 아닙니다.**

- 상태 관리(전역 변수 → Zustand), 라우팅(DOM 속성 토글 → React Router), SSE(모듈 싱글톤 → 클로저 캡슐화 + 훅) 등 핵심 패러다임이 **의도적으로 React-way로 재설계**되었습니다.
- 아키텍처는 Feature Slices 원칙에 따라 정돈되어 있고, 단방향 의존성이 잘 유지됩니다.
- 다만 **테스트 실패 30건**과 **일부 고위험 영역의 낮은 커버리지**(설정 패널, 툴팁, 클립보드)는 즉각적인 정리가 필요합니다.
- i18n/CSS의 레거시 병존은 **의도적이며 통제된 기술 부채**로, 후속 페이즈에서 점진 제거 가능합니다.

**종합 판정: 마이그레이션은 구조적으로 성공적이나, 테스트 품질을 P0로 정리해야 운영 안정성이 확보됩니다.**
