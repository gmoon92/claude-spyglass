## 0. 요약 (결정)

1. **병존 기간에는 classic `<script>` 3종을 그대로 유지**한다 (`i18n.js` → `i18n-dom.js` → `lang-switcher.js`). i18n ESM화는 별도 트랙으로 분리하며 P1-03 범위가 아니다.
2. React 컴포넌트는 `window.I18n` 을 직접 읽지 않고 **`useI18n` 훅 어댑터**를 통해 읽는다. 훅은 `window.I18n` 위의 얇은 래퍼이며, `I18n.onChange` 구독으로 언어 전환 시 리렌더를 트리거한다.
3. **스냅샷 결정론은 현행 모킹 패턴(`window.I18n.t` 스텁 + `Date.now` 고정)을 그대로 보존**한다. 어댑터는 모킹 표면을 바꾸지 않으므로 `renderers.test.ts`/`formatters.test.ts`의 골든마스터가 깨지지 않는다.

핵심 근거 한 줄: **현재 39개 ESM 소비 파일 중 `i18n.js`에서 `import`하는 파일은 0건이며, 전부 `window.I18n` 런타임 전역으로 소비한다.** 즉 "classic script가 전역을 노출하고 ESM이 그 전역을 읽는" 구조는 React 도입 이전부터 production에서 동작 중이다 — React 어댑터는 이 검증된 경계를 그대로 잇는다.

## 2. classic script 3종 식별

운영 진입 `packages/web/index.html` 말미 로드 순서 (`index.html:975-978`):

```
975  <script src="/assets/js/i18n.js"></script>          ← (1) 코어: window.I18n 노출 + DOMContentLoaded 자동 init
976  <script src="/assets/js/i18n-dom.js"></script>       ← (2) data-i18n 속성 DOM 자동 번역
977  <script src="/assets/js/lang-switcher.js"></script>  ← (3) #lang-switcher 드롭다운 핸들러
978  <script type="module" src="/assets/js/main.js"></script>  ← ESM 진입(앞 3종에 의존)
```

3종 모두 **IIFE 전역 노출** 패턴(번들러 없음):

| # | 파일 | 역할 | 전역/의존 근거 |
| - | ---- | ---- | -------------- |
| 1 | `assets/js/i18n.js` | 코어. `window.I18n` 노출, 언어 결정(URL→localStorage→navigator→ko), locales fetch, `t/setLang/getLang/onChange` | `i18n.js:18` IIFE, `:282` `window.I18n = I18n;`, `:285-289` `DOMContentLoaded`에서 `I18n.init()` 자동 호출 |

## 3. 결정: 병존 전략

### 3.1 classic script 3종 유지 (회귀 최소화)

- **유지 근거**:
  - 39개 소비 파일이 `window.I18n` 전역에 직접 결합. classic script를 제거/ESM화하면 39파일 동시 변경 → 회귀 표면 최대화.
  - locales 로딩은 `i18n.js:87` `fetch('/locales/${lang}/${ns}.json')` 런타임 fetch이며, Vite는 이 경로를 `/locales` 프록시로 위임(`vite.config.ts:16` PROXY_PREFIXES에 `/locales` 포함). 즉 dev/prod 모두 classic fetch 경로가 그대로 동작.
  - locales 자산 구조 실측: `packages/web/locales/{ko,en,ja,zh}/{badges,common,request,session,ui}.json` — `i18n.js:21-22` SUPPORTED_LANGS·NAMESPACES와 1:1.
- **i18n ESM화는 별도 트랙**: `i18n.js`를 ESM 모듈(`export`)로 재작성하거나 i18next류로 교체하는 작업은 P1-03 범위 밖. 39파일이 React로 모두 이식 완료된 이후(후속 페이즈)에 단일 트랙으로 처리. 본 문서는 "병존 기간 classic 유지"만 확정.

### 3.2 React 진입(index.react.html)에 classic script 3종 주입 — **확인된 GAP**

- **실측 GAP**: P1-01 스캐폴드 산출 `packages/web/index.react.html` 은 `<script type="module" src="/src/main.tsx"></script>` **단 1줄만** 로드한다(`index.react.html:11`). classic i18n script 3종이 **없다**. `src/main.tsx` 에도 i18n 참조 0건.
- **함의**: React 컴포넌트가 `window.I18n.t(...)` 를 호출하는 순간 `window.I18n` 이 `undefined` 라 런타임 에러. 또한 `[data-i18n]` DOM 자동 번역(i18n-dom.js)·언어 스위처(lang-switcher.js)도 미작동.
- **해결 (병존 전략의 일부, 코드는 후속 task가 적용)**: React 진입 HTML에 운영 `index.html:14-40`(FOUC 인라인) + `:975-977`(classic 3종)을 `main.tsx` 모듈 로드 **앞에** 동일 순서로 주입.
  - 순서 불변식: `i18n.js`(전역+자동 init) → `i18n-dom.js` → `lang-switcher.js` → `type=module` 진입.
  - 근거: `i18n-dom.js:67-71`·`lang-switcher.js:34-39` 가 `window.I18n` 선존재를 전제(미존재 시 warn 후 no-op).
- **초기화 타이밍**: `i18n.js:285-289` 가 `DOMContentLoaded`에서 `I18n.init()`(비동기 locales fetch)을 호출. React 트리가 첫 렌더에서 `t()`를 호출할 때 locales가 아직 fetch 전이면 `t()`는 **키 자체를 반환**(`i18n.js:212-225` 미스 폴백). FOUC/키노출을 피하려면 `useI18n` 훅이 `I18n.init()` Promise 완료를 게이트하거나(섹션 4.2), 최소한 `onChange` 후 리렌더로 자가 치유되게 한다.

### 3.3 React 어댑터: `useI18n` 훅 전략

목표: 컴포넌트가 `window.I18n` 을 직접 만지지 않고, 언어 전환 시 자동 리렌더되는 단일 접점을 갖는다.

설계 골자 (코드 아님, 계약만):

- **읽기 표면**: `useI18n()` 은 `{ t, lang }` 를 반환. `t` 는 `window.I18n.t` 를 그대로 위임(`globals.d.ts:22` 시그니처 미러). `lang` 은 `window.I18n.getLang()`(`globals.d.ts:25`).
- **리렌더 트리거**: 훅 내부 `useEffect`에서 `window.I18n.onChange((lang) => setLang(lang))` 구독, cleanup에서 unsubscribe. `onChange`는 `i18n.js:272-278` 가 unsubscribe 함수를 반환하므로 React cleanup과 1:1 정합. 언어 변경 시 `i18n.js:246-248` 가 리스너를 호출 → 훅이 상태 갱신 → 구독 컴포넌트 리렌더.
  - 단, `lang-switcher.js:48-50` 현 구현은 `setLang` 후 `window.location.reload()` 로 전체 리로드한다. 병존 기간엔 이 리로드가 React 트리도 재초기화하므로 onChange-리렌더와 리로드가 **중복**이지만 회귀는 아니다(리로드가 우선). 리로드 제거(SPA 내 무리로드 언어전환)는 React 단독 진입 전환(P4-07) 이후 별도 결정.
- **방어 가드**: SSR/초기 미초기화 대비 `window.I18n?.t?.(...) ?? key` 폴백 — `i18n-utils.js:14`·`:45`·`:52` 가 이미 쓰는 옵셔널 체이닝 패턴과 동일. 훅도 동일 가드를 채택해 `window.I18n` 미주입 시(섹션 3.2 GAP 미해결 상황) 크래시 대신 키 폴백.
- **locale/Collator/날짜레이블**: 신규 추상화 만들지 말고 **기존 `i18n-utils.js` ESM export 재사용**(`getLocale`/`getCollator`/`formatDateRangeLabel`, `i18n-utils.js:13`·`:24`·`:40`). React 컴포넌트는 이 모듈을 그대로 import — 이미 6개 ESM 모듈이 import 중이라 검증된 경로.
- **확장 금지(over-engineering 가드)**: i18next·react-i18next·Context Provider 신규 도입 금지. 병존 목적은 "검증된 전역을 React에서 안전하게 읽기"이며, 새 i18n 런타임을 끼우면 39파일 vs 신규 React 컴포넌트 간 **이중 SSoT**가 생겨 번역 키 드리프트·로딩 경쟁 발생. `useI18n`은 `window.I18n` 위 얇은 래퍼로 한정.

## 4. 스냅샷 결정론 보존 (골든마스터 보호)

### 4.1 현행 모킹 패턴 (실측)

두 테스트가 동일 패턴으로 결정론을 확보:

- `renderers.test.ts:11-38`: `beforeAll`에서

  - `Date.now = () => NOW_FIXED_MS`(`:37`, `NOW_FIXED_MS = 2026-05-04T10:00:00Z` `:8`). fixture timestamp(`2026-04-28T10:00:00Z`) 기준 정확히 6일 후 고정 → `fmtRelative` "6일 전" 스냅샷 안정.
  - `afterAll`(`:40-42`)에서 `Date.now` 복원.
- `formatters.test.ts:5-18`: `beforeAll`에서 동일하게 `window.I18n.t` 스텁(`common.formatters.*` 키 4종 맵).

baseline 실측: `bun test renderers.test.ts formatters.test.ts` → **73 pass / 0 fail, 20 snapshots, 105 expect** (worktree 현재 상태).

### 4.2 보존 전략 — **모킹 표면 불변**

- **불변식**: 테스트는 `window.I18n.t` 라는 전역 표면을 모킹한다. `useI18n` 훅이 내부에서 `window.I18n.t` 를 위임하는 한, **훅 도입은 모킹 표면을 바꾸지 않는다**. 따라서 `renderers.test.ts`/`formatters.test.ts`의 스텁이 그대로 유효.
- **순수 렌더러는 훅을 거치지 않는다**: `makeRequestRow`/`makeTargetCell`/`makeSessionRow`(`renderers.test.ts:2` import)는 문자열 HTML을 반환하는 순수 함수로, 내부에서 `window.I18n.t`를 직접 호출(`badges.js:107` 등 경로). 이들은 React 컴포넌트가 아니므로 React 이식 시에도 **순수 함수 계약을 유지**해야 골든마스터가 보존된다. 즉 "렌더러를 컴포넌트로 흡수하며 `useI18n`을 안에서 호출"하는 리팩토링은 스냅샷을 깨뜨린다 → **금지**. 렌더러는 `window.I18n.t` 직접 호출(또는 주입식 `t` 파라미터)로 두고, 컴포넌트는 그 출력 문자열을 소비.
- **React 컴포넌트 신규 테스트**: 만약 컴포넌트 단위 테스트를 추가한다면 동일 `window.I18n.t` 스텁을 `beforeAll`에서 주입(현 패턴 복제). `useI18n`은 `window.I18n`을 읽으므로 별도 모킹 인프라 불필요 — **스텁 1벌로 순수 렌더러·훅·컴포넌트 모두 커버**.
- **Date.now 고정 유지**: 상대시간을 출력하는 모든 스냅샷은 `Date.now` 고정에 의존(`renderers.test.ts:37`). React 이식 후에도 시간 의존 출력은 순수 함수(`fmtRelative` 등 `formatters.js`)에 남겨 `Date.now` 모킹으로 결정론 확보. 컴포넌트가 `new Date()`/`Date.now()`를 직접 호출하면 모킹이 닿지 않을 수 있으므로, 시간 포맷은 반드시 `formatters.js` 경유.
- **테스트 러너 불변**: P1-06(bun test 유지)과 정합. `bun:test`의 `toMatchSnapshot`·`beforeAll/afterAll` 그대로 사용.

### 4.3 결정론 회귀 방지 체크리스트 (후속 task용)

1. `useI18n` 훅은 `window.I18n.t`를 **위임만** 한다(키→번역 매핑 로직 재구현 금지). → 모킹 표면 1개 유지.
2. 순수 렌더러(`makeRequestRow` 등)는 React 컴포넌트로 합치지 않고 순수 함수로 보존. → 기존 20 스냅샷 불변.
3. 시간 포맷은 `formatters.js` 경유 — 컴포넌트 직접 `Date.now()` 금지. → `Date.now` 모킹 유효.
4. React 컴포넌트 테스트 추가 시 `beforeAll`에서 `window.I18n.t` 스텁 주입(섹션 4.1 맵 복제). → 신규 테스트도 결정론.
