## 2. P4-02 / P4-03 분담 경계

두 task가 같은 4파일을 나눠 가지므로 **절단선이 겹치지 않게** 못박는다. 절단 기준 = "그 분할이 소비하는 데이터/이벤트 출처를 누가 먼저 이식하는가". tasks.json상 P4-03 depends_on:["P4-02"]이므로 **P4-02가 셸+데이터 훅의 토대를 깔고, P4-03이 그 위에 flow/tool-stats를 얹는** 순서다.

### 2.1 P4-02 — catalog 테이블 + 검색 → `MetaDocsCatalog`/`MetaDocsSearch` TSX

- **소유 파일**: `meta-docs-view.js` 중 catalog/search/filters/fetch/summary-cards/refresh 군집(§1의 분할 1·2·3·데이터 fetch·sidebar·refresh).
- **catalog 경계**: `renderHtml`/`rowHtml`/`thHtml`/`metaDocTypeBadge`/`pathCellHtml`(view.js:647-834)의 innerHTML 문자열 빌더 → JSX. **정렬 로직(`applySort`/`COMPARATORS`/`DEFAULT_DIR`/`SORTABLE_KEYS`/`cmpString`/`cmpNumber`, view.js:1247-1337)은 순수 함수 lib(`lib/meta-docs-sort.ts`)로 1:1 이식** — 컴포넌트에 인라인 재구현 금지(P4-02 done_criteria "검색 필터 회귀 0"의 정렬 동치 보장).
- **`applyDisplayFilter`(view.js:1223)** = 행 부분집합(all/unused/orphan) 순수 함수 → 동일 lib 또는 store selector.
- **SSoT 경유 강제 (architecture.md:96)**: `metaDocTypeBadge`(view.js:811)는 `toolIconHtml('Agent'/'Skill')` + `.tool-chip-{kind}` 색 토큰에 위임. JSX에서 hex/글리프 직접 지정 금지 — `render/badges.js#toolIconHtml`를 컴포넌트로 1:1 이식(render군 P3-09와 공유, badges.js:52 주석이 meta-docs 호출 명시).
- **sort-head/filter-btn/tab 재사용**: 현재 `renderSortHead`/`renderFilterBtn`/`renderTab`(view.js:31-33)의 `.replace()` 문자열 후처리(view.js:101-104, 864-872)는 **디자인시스템 컴포넌트가 TSX화되면(P2 design-system) `<SortHead>`/`<FilterBtn>`/`<Tab>` props로 자연 소멸**. `.replace` 패턴은 이식 금지(JSX에서 className/data-* 직접 부여).
- **로컬 헬퍼 추출 주의**: `shortenPath`(view.js:1339)·`formatTokens`(view.js:1354)는 meta-docs-view에만 정의된 로컬 함수(grep: 타 파일 중복 0). 헤더 주석(view.js:20)이 "기존 헬퍼 재사용"이라 적었으나 **실제로는 로컬 정의** — `lib/`로 추출하되 formatters.js의 기존 `fmtTime`(import됨, view.js:23)과 동거. 새 3번째 사본 생성 금지.
- **search 경계**: `applySearchFilter`(view.js:1014)는 DOM `row.hidden` 토글(이름 부분일치, 대소문자 무시) → **store searchTerm 파생 visibility**로. 현재 re-fetch 없이 즉시 hide/show(view.js:1001 주석)이므로 derived selector가 정확히 1:1. `highlightDeepLinkRow`(view.js:381)는 `openMetaDocViaDeepLink` 전용이나 **그 호출자가 이미 제거됨**(main.js:17) → §7에서 폐기 후보로 분류.
- **date-range 의존**: catalog fetch가 `getDateRange()`(view.js:460, api.js:213)를 읽음 → P2-08(date-range-dropdown TSX) + P3-03(api 역전) 결과를 구독. tasks.json P4-01 test_strategy: "getDateRange(api)만 의존 → P3-03 이전 착수 가능" — 단 P4-02는 depends_on에 P2-08을 명시하므로 date-range 컴포넌트는 선행.

### 2.2 P4-03 — flow(ego-graph) + tool-stats → TSX 통합

- **소유 파일**: `meta-docs-flow.js` + `meta-docs-flow-camera.js` + `meta-docs-flow-highlight.js` 전량 + view의 셸/탭/flow 트리거 군집(§1의 분할 4·5·셸).

## 3. 상태 분류 (로컬 vs 스토어) — scopeMode/searchTerm/activeRow 확정

P4-01 done_criteria 핵심: "scopeMode/searchText/activeRow 상태 매핑 확정". 현 구현은 **모든 메타 필터 상태가 `meta-docs-view.js`의 모듈 `state` 객체(view.js:54-68)에 로컬 보관**되고, `appMode`/`metaSubTab`만 `state.js`(P1-04 store 대상, state.js:14,17)에 있다.

|------|----------|------|------|
| `scopeMode` ('selected'\|'all') | view.js:58 (모듈 state) | **스토어** — main.js selectProject가 setMetaScopeMode로 외부 변경(main.js:266,302), summary 카드·flow·catalog 3개가 공유 | view.js:215, main.js:266,302 |

| `activeRow` (activeFlowRow) | DOM `[data-flow-active]` 속성 (JS 상태 아님) | **로컬(셸) 또는 스토어 — catalog↔flow 계약값** | view.js:990-997, 967 |

**확정 매핑**:
1. **scopeMode → 스토어** (필수). main.js(selectProject)가 외부에서 set하고 3개 컴포넌트가 읽으므로 모듈 로컬로 두면 React 트리 밖 변경을 구독 불가. P1-04 메타 슬라이스에 `scopeMode` 추가.
2. **searchText → 스토어** (권장). 탭/필터 재진입 보존이 명세(view.js:540)이고, deep-link set(view.js:367)이 트리 밖에서 올 수 있어 store가 안전. 단 catalog 단일 소비면 셸 로컬도 허용.
3. **activeRow → catalog↔flow 단방향 props/store** (계약값). DOM dataset(view.js:996) 폐기 → 명시 상태. flow가 catalog 하위가 아니라 형제(트리 §1.1)이므로 **공통 부모(`MetaDocsPage`) 로컬 또는 store**로 끌어올려 양쪽이 구독.

회귀 위험: 현재 scopeMode/searchTerm은 **탭 재진입 시 유지**가 명세(view.js:51 "탭 재진입 시 유지"). React unmount 시 로컬 상태는 소멸 → **store로 올리지 않으면 탭 전환 후 필터/검색어가 초기화되는 회귀**. 위 1·2를 store로 확정하는 직접 근거.

## 4. flow의 SVG/camera/highlight 명령형 로직 처리 (P3-01 canvas 패턴 준용)

flow는 web에서 **가장 명령형(imperative) 비중이 큰 모듈**이다 — viewBox 줌/팬, rAF 카메라 트윈, foreignObject 자연폭 재측정, 드래그 z-index reappend, BFS path highlight 모두 직접 DOM/SVG 조작. P3-01의 `chart.js → Chart.tsx useRef 캡슐화`(tasks.json P3-01: "useRef canvas 컴포넌트 캡슐화")가 **직접 선례**다.

### 4.1 React에서 격리할 명령형 영역 (`<MetaDocsFlow>` useRef escape-hatch)

| 명령형 로직 | 함수 | 라인 | React 처리 |

### 4.2 처리 방안 결정

- **`<MetaDocsFlow>`는 P3-01 Chart.tsx와 동일하게 "thin React 껍데기 + useRef escape-hatch"**. 노드/엣지 SVG 빌드·줌/팬·드래그·하이라이트는 effect 내부에 **현 명령형 코드를 거의 그대로 이식**한다. 노드를 JSX `<foreignObject>` N개로 선언 매핑하지 **않는다** — `resizeNodeToContent`의 동기 `offsetWidth` 측정(flow.js:596)이 선언적 렌더와 충돌(측정 시점 보장 불가).
- **순수 추출 대상** (effect에서 호출하는 lib):
  - camera.js 전량 → `lib/flow-camera.ts` (rAF/이징/fit 계산, 외부 의존 0, camera.js:9).
  - highlight.js의 BFS(`buildAdjacency`/`bfsCollect`) → `lib/flow-graph.ts` (순수, highlight.js:20). DOM 클래스 토글부(`applyFullPathSelection` 등)는 컴포넌트 effect로.
  - 엣지 좌표(`computeEdgeD`/`chooseAnchors`/`anchorPoint`/`offsetOutward`, flow.js:672-731) → `lib/flow-edge.ts` (순수 기하).
  - `computePositions`/`contentBBox`(flow.js:318,1142) → `lib/flow-layout.ts` (순수).
- **모듈 상태(`_nodes`/`_edges`/`_seqView`/`_nodeIndex`/`_edgeIndex`/`_lastArgs`, flow.js:109-117) → useRef**. React 리렌더와 무관한 가변 가시화 상태이므로 state가 아니라 ref. `reloadLast`(flow.js:281)의 `_lastArgs` 보존은 ref + props(activeRow) 조합.
- **회귀 위험 (★flow 최대 위험)**: 등록 순서가 정책의 일부(flow.js:260-277 — bindSubRowClick이 bindHighlight보다 먼저, stopImmediatePropagation 의존). effect로 옮길 때 **리스너 등록 순서를 보존**하지 않으면 sub-row 클릭이 카드 재중심으로 흡수되는 회귀(flow.js:770 주석). + pan-click suppress(flow.js:1004-1018), drag-vs-click 4px 임계(flow.js:884) 모두 단위테스트 불충분 → **수동 verify 필수**(P3-01의 resize verify 체크리스트 패턴 준용, tasks.json P3-01 test_strategy).
- **suppression-marker 검증**: P3-01과 동일하게 "리사이즈/줌/팬/드래그 후 깜빡임 0 + 하이라이트 정상 + sub-row 재중심 정상"을 before/after 증거로.

## 8. .js 폐기 종료조건

P4-03 done_criteria: "meta-docs-view.js·meta-docs-flow.js 삭제 + 잔여 import 0(grep)". 4파일 전체의 **삭제 가능 시점**:
