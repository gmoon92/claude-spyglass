### 0.1 task 명칭과 실제 구조의 불일치 (중요)

P2-05/06/07 task 는 영역을 **"진단/Hook/Graph DB/Proxy 4영역"** 으로 명명한다(tasks.json:301). 그러나 실제 `renderActiveTab()` 라우터(settings-view.js:142-152)는 **6개 sub-tab** 을 분기한다:

```
diag / hooks / graph / sqlite / proxy / server   (settings-view.js:144-149)
```

즉 task 가 명시한 4영역 외에 **SQLite**(:1062 `renderSqliteSection`)와 **Server/로그**(:1460 `renderServerSection`) 2개 섹션이 더 존재한다. 파일 헤더 주석도 "진단 + Hook + Graph DB + Proxy + 서버/로그"로 5영역을 명시한다(settings-view.js:2). 본 문서는 4영역 명세를 따르되, **누락 2영역의 귀속을 명시적으로 결정**한다(§4.3) — 그러지 않으면 settings-view.js 삭제 종료조건(잔여 import 0)이 성립하지 못한다.

## 4. 폼 상태·핸들러·모달/토스트 처리 방안

### 4.1 폼 상태: 로컬(useState) vs 스토어(Zustand)

판단 기준: **여러 sub-tab/세션에 걸쳐 공유되거나 영속이 필요하면 스토어, 단일 폼 내 휘발성이면 로컬**(architecture.md:64 stores 는 UI 를 모름 — 순수 UI 토글은 로컬).

| 구 전역 상태(:라인) | 성격 | 결정 | 근거 |
| ------------------- | ---- | ---- | ---- |
| `_activeTab` :67 | 어느 sub-tab 활성 | **스토어** (settings 슬라이스, P1-04 라우팅 슬라이스와 정합) | jump 버튼(:354)·rail 진입이 외부에서 탭 전환 → 공유 필요 |
| `_generation` :64 | in-flight fetch 가드 카운터 | **제거** → React 패턴으로 대체 | useEffect cleanup + AbortController 가 정석. enter/exit 의 generation 증가(:84,:96)는 언마운트 cleanup 으로 자연 해소 |
| `_selectedProfile` :374 | Hook 프로필 라디오 (full/minimal) | **로컬**(HooksPanel useState) | 단일 폼 내 선택, 영속 불필요 |
| `_proxyShell` :1160 | Proxy 셸 선택 (auto/zsh/bash/fish) | **로컬**(ProxyPanel useState) | 단일 폼 내 선택, 셸 변경 시 재fetch(:1331) 트리거 |

> diag/graph/sqlite/proxy/server 의 fetch 응답 데이터(`data`, `ladybug`, `info`, `statusData` 등)는 **스토어에 두지 않는다** — 재진입 시 항상 최신 fetch(파일 헤더 디자인 결정 :21 "stale-while-revalidate 없이 단순화"). React 에선 컴포넌트 마운트 시 fetch 하는 로컬 상태 + 수동 refetch(refresh 버튼 :134) 로 동치. 다만 데이터 페칭은 단순 useEffect 또는 경량 useQuery 훅으로 캡슐화(원본의 6중복 try/catch+generation 가드 패턴 :177-190 등을 1개 훅으로 통합 권장).

### 4.2 제출/검증 핸들러

원본은 검증 로직이 거의 없다(백엔드 신뢰 — 파일 헤더 :23 "confirm 모달 없이 직접 호출"). React 이식 시:

- **제출 핸들러** = `onHookPreview/onHookApply`(:517,531), `onGraphMode`(:1013), `onLadybugInstall`(:904), `onProxyInstall/Restore`(:1348,1416) → 컴포넌트 내 async 함수 + 결과를 result **로컬 상태**로. 테스트는 `apiFetch`(fetch) mock 후 입력→호출 인자 검증(tasks.json:323,338).

## 5. 이식 시 주의점 (회귀 위험 지점)

### 5.1 in-flight fetch 가드 (`_generation`)
`renderDiagSection` 등 6개 렌더 함수가 `gen = _generation` 캡처 후 await 뒤 `if (gen !== _generation) return`(예: :177,186,190)으로 stale setState 를 막는다. enter/exit 가 `_generation++`(:84,96). React 이식 시 **AbortController + useEffect cleanup** 으로 대체 — sub-tab 전환/언마운트 시 in-flight 응답 무시. 이 신규 cleanup 계약은 원본 미보장 영역과 동치이므로 **신계약**(constraints.regression_gate:7).

### 5.2 result slot 부분 교체
preview/apply/install/restore 결과는 컨테이너 전체가 아닌 `#hookResult`/`#ladybugInstallResult`/`#proxyResult`/`#graphResult` 부분만 갱신(:494,889,834,1320). React 에선 패널 컴포넌트의 **result 로컬 상태** 로 자연 대체. 부분 갱신 후 일정 시간 뒤 전체 재렌더(`setTimeout(...renderProxySection)` :1392,1443 / `renderGraphSection` :1001,1043)는 **refetch 트리거**(상태 무효화)로 치환.

### 5.3 SSE 스트림 (`onLadybugInstall` :904-1003)
유일하게 fetch reader 루프로 SSE 를 직접 파싱(`res.body.getReader()` :944, `\n\n` 분할 :953, `data:` 라인 필터 :958). 이는 P4-04 `useSSE` 훅(EventSource 기반)과 **다른 메커니즘**(POST 응답 스트림). GraphPanel 이식 시 별도 처리 — `useSSE` 로 흡수하지 말고 install 전용 스트리밍 핸들러로 유지하되, AbortController cleanup 추가. Zod 검증(P1-07)은 `evt.type`(start/stdout/stderr/done :963-969) 파싱부에 적용 가능.

### 5.4 jump 버튼 cross-tab 전환
diag 행의 `data-settings-jump`(:253,257,267,270,324,336,340) 클릭이 `_activeTab` 변경 + 재렌더(:350-359). React 에선 스토어의 settings activeTab 액션 호출로 — DiagPanel → 스토어 → SettingsView 라우터 리렌더. (§4.1 `_activeTab` 스토어 결정의 근거.)

### 5.5 idempotent 바인딩 마커
`dataset.bound==='1'` 가드(`bindNav` :110, `bindRefresh` :136)는 명령형 재바인딩 중복 방지용. React 선언형에선 **불필요**(이벤트는 JSX onClick) → 제거.
