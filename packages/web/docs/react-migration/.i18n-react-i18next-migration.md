# i18n — react-i18next 정공법 마이그레이션 (v4.0.9)

> 작성: 2026-06-02 | 상태: **기능 완료(언어 변경 reload 제거 + 반응형 전환)**, 직접 tt() 점진 전환 잔여
> 관련: `.migration-gap-report-i18n.md`

---

## 1. 배경 / 문제

레거시는 전역 IIFE `window.I18n`(`assets/js/i18n.js`) + 어댑터 `tt()`(`src/app/i18n-labeler.ts`)로 i18n 처리.
React 컴포넌트가 `window.I18n` 메모리 변경을 감지 못해, 언어 변경 시 `lang-switcher.js:50` 의
`window.location.reload()` 로 SPA 를 통째로 새로고침했다(상태 파괴).

## 2. 채택 아키텍처 (react-i18next)

- 의존성: `i18next` / `react-i18next` / `i18next-http-backend` (`packages/web/package.json`).
- 인스턴스: `src/lib/i18n.ts`.
  - **기존 키 문자열 무변경**이 핵심 설계. 레거시 키는 `<ns>.<path>`(첫 세그먼트=ns) 형태인데,
    5개 레거시 ns(common/request/badges/session/ui)를 **단일 'translation' ns 아래 ns명으로 병합**
    로드하는 커스텀 백엔드 + `nsSeparator: false` + `keySeparator: '.'` 로 `ui.foo.bar` 를 그대로 해석.
  - 보간: 레거시 `{var}`(단일 중괄호) → `interpolation.prefix/suffix = '{'/'}'`(JSON 무재작성).
  - 로딩: `/locales/{lng}/{ns}.json` 언어 단위 lazy(레거시와 동일 경로).
  - 언어 결정: 레거시 `resolveLang`(URL ?lang → localStorage['spyglass:lang'] → navigator → 'ko') 1:1.
  - `react: { useSuspense: false }` (SSR/테스트 렌더 중 suspend 회피).
  - **전환기 폴백**: `parseMissingKeyHandler` 가 리소스 미스 키를 `window.I18n.t` 로 위임(프로덕션
    키-플래시 방지). 상세는 `src/lib/i18n.ts` 주석 참조.

## 3. 전환 흐름 (reload 없는 반응형)

`src/main.tsx` 의 브릿지: `window.I18n.onChange(lng => i18next.changeLanguage(lng))` + 초기 언어 동기.

```
lang-switcher select change
  → I18n.setLang(lng)  // localStorage 저장 + locale 로드 + window.I18n 갱신 + onChange 발화
  → (브릿지) i18next.changeLanguage(lng)
  → useTranslation 구독 컴포넌트/레이아웃 재렌더 + memo 자식 labeler ref 갱신
  → SPA 상태 보존한 채 전 UI 새 언어 전환 (reload 없음)
```

## 4. 컴포넌트 전환 패턴

- **JSX 렌더 컴포넌트**: `const { t } = useTranslation();` + `window.I18n.t(` → `t(`.
- **함수로 호출되는 컴포넌트**(예: `SessionRow` — `SessionList` 가 `SessionRow({...})` 로 호출): 훅 불가 →
  `t` 를 **옵셔널 prop**(미주입 시 `window.I18n.t` 폴백)으로 받음. rules-of-hooks 회피.
- **모듈 헬퍼**(예: `FlowHead.complexityOf`, `Chip.a11yProps`): `t` 를 **인자**로 주입.
- **레이아웃**(AppShell/BrowseLayout/MetaDocsLayout/SettingsLayout/BrowseSidebar): `useTranslation()` 구독
  (언어 변경 시 재렌더). memo 된 자식에 가는 labeler 는 `useMemo([..., i18n.language])` 로 새 ref 전달
  (AppShell 은 memo chrome 에 `t={t}` 주입). 직접 `tt()` 는 재렌더로 재평가(window.I18n 동기).

## 5. 테스트 전략

- `vitest.setup.ts`: `src/lib/i18n` import(i18next init) + **테스트 한정** i18next `t`/`getFixedT` 를
  `window.I18n.t`(테스트 stub)로 **완전 위임**(vars 포함). → 골든/특성/동치 테스트가 바닐라(window.I18n)
  ↔ TSX(useTranslation) 를 동일 i18n 출처로 비교(1282 그린 보존).
- 함수호출-컴포넌트 null 검사 테스트는 `renderToStaticMarkup` 렌더(빈 마크업)로 교정(직접 호출 시 invalid hook).

## 6. 잔여 작업 (점진 — 무해)

현재 reload 없이 반응형 동작하지만 아래는 점진 정리 대상:

- **직접 `tt()` 잔존**: 레이아웃의 직접 tt() 호출 다수 + `use-tooltip.ts`(hover 시점 tt 재평가) +
  meta-docs/dashboard 일부. window.I18n 동기 + 레이아웃 useTranslation 구독으로 반응하나, 정공법
  완성을 위해 `useTranslation().t` 로 점진 전환 권장. (남은 tt 사용처: `grep -rn "\btt(" src`.)
- **locales 이중 fetch**: 전환기 동안 레거시 `i18n.js`(window.I18n) + react-i18next 백엔드가 각각
  `/locales` 를 fetch. 전 컴포넌트 전환 + 레거시 `i18n.js` 의존 제거 후 단일화.
- **vendor 번들**: i18next 계열로 vendor +~50kB. 전환 완료 후 레거시 i18n.js 제거로 일부 상쇄 가능.
- **검증 미완**: 1282 테스트/빌드 통과. 단 **브라우저에서 "언어 전환 시 전 UI 갱신" 시각 확인 필요**
  (특히 깊이 memo 된 컴포넌트). `?lang=en` 또는 lang-switcher 로 확인.

## 7. 다른 컴퓨터에서 이어받기

1. `git pull` → `bun install`(또는 `bun run start`/`dev` 가 `scripts/ensure-deps.ts` 로 i18next 자동 설치).
2. 잔여 직접 tt() 를 청크 단위(6대 도메인)로 `useTranslation().t` 전환, 청크별 `npm test`(1282) 게이트.
3. 전 컴포넌트 전환 후 레거시 `assets/js/i18n.js`/`i18n-dom.js` window.I18n 의존 제거 + `i18n-labeler.tt`
   폐기 + `vitest.setup` 위임/`i18n.ts` parseMissingKeyHandler 폴백 정리.
