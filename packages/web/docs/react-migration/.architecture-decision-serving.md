## 1. Vite outDir/base/assetsDir ↔ dispatch.ts 서빙 경로 정합 매핑표

dispatch 의 정적 서빙 분기는 4곳이다: `/`(`dispatch.ts:99-132`), `/assets/*`(`dispatch.ts:134-150`), `/locales/*`(`dispatch.ts:152-164`), `favicon`(`dispatch.ts:166-175`). 정적 루트는 `WEB_ROOT`(`dispatch.ts:26-28`)이고 `webFile(subPath)`(`dispatch.ts:31-33`)가 `Bun.file(pathJoin(WEB_ROOT, subPath))` 로 연다.

| Vite 산출(설정 근거) | dist 내 실제 경로 | dispatch URL 분기(근거) | webFile 해석 경로 | 정합 |
|---|---|---|---|---|
| `outDir:dist` (`vite.config.ts:38`) | `packages/web/dist/` | — (`WEB_ROOT` 기준점) | `WEB_ROOT=…/dist/` | WEB_ROOT→dist 전환 필요 (§2) |
| `base:'/'` (`vite.config.ts:34`) | 자산 URL이 `/assets/…` 절대경로로 주입 | `/assets/` 강결합 (`dispatch.ts:135`) | — | 정합 (base 가 `/` 라 URL 접두 동일) |
| `assetsDir:'assets'` (`vite.config.ts:39`) | `dist/assets/index.react-<hash>.js`(+`.map`) | `/assets/*` (`dispatch.ts:134-150`) | `WEB_ROOT/assets/*` | 정합 (실측 §1-2) |
| 진입 HTML | `dist/index.react.html` (실측) | `webFile('/index.html')` (`dispatch.ts:122`) | `WEB_ROOT/index.html` | **불일치** — 파일명 mismatch (§1-3, F1) |
| `/locales` (Vite 미복사) | `dist/locales/` **부재**(실측) | `/locales/*` (`dispatch.ts:152-164`) | `WEB_ROOT/locales/*` | **불일치** — publicDir 미설정 (§3, F2) |
| favicon | `dist/favicon.svg` (publicDir 시) | `/favicon.svg|ico` (`dispatch.ts:166-175`) | `WEB_ROOT/favicon.*` | publicDir 복사 의존 (§3) |

### 1-1. base/assetsDir 가 `/assets/` 계약을 보존하는 이유

`vite.config.ts:34-39` 의 `base:'/'` + `assetsDir:'assets'` 조합은 빌드 산출 HTML에 자산을 `/assets/…` **절대경로**로 주입한다. dispatch 의 정적 서빙은 `path.startsWith('/assets/')` 에 강결합(`dispatch.ts:135`)이므로, 이 URL 접두가 1:1로 일치해 데몬이 무수정으로 자산을 라우팅한다. `assetsDir` 를 `assets` 로 고정한 의도는 `vite.config.ts:35-36` 주석에 명시("데몬 dispatch 가 /assets/ prefix 로만 정적 파일을 찾으므로").

### 1-2. 실측 — 빌드 산출이 매핑표를 확증

P1-01 `vite build` 산출물(실측):
```
packages/web/dist/
  index.react.html                       ← 자산 link 주입됨
  assets/
    index.react-D7gYVX1f.js              ← 번들 엔트리
    index.react-D7gYVX1f.js.map          ← sourcemap (build.sourcemap:true, vite.config.ts:41)
```
`dist/index.react.html` 의 주입 결과는 `<script type="module" crossorigin src="/assets/index.react-D7gYVX1f.js">` — `/assets/` 절대경로로 떨어져 `dispatch.ts:135` 분기와 정합. 따라서 **자산 URL 계약은 검증됨**.

### 1-3. F1 — 진입 HTML 파일명 불일치 (신규 발견, 결정 필요)

- 현재 빌드 진입은 `index.react.html`(`vite.config.ts:44` `input: …/index.react.html`)이고, 산출도 `dist/index.react.html`(실측). 반면 dispatch 의 루트 분기는 `webFile('/index.html')` 고정(`dispatch.ts:122`).
- P1-01 산출 `index.react.html` 은 **"운영 진입 전환은 P4-07"** 로 명시된 검증 전용 엔트리(`index.react.html:6`, `vite.config.ts:43`).
- 따라서 WEB_ROOT→dist 만 바꾸면 `dist/index.html` 부재로 루트(`/`)가 깨진다. 운영 진입을 React로 전환하는 시점(P4-07)에 산출 파일명을 `index.html` 로 맞추거나(`input` 을 `index.html` 로 교체), dispatch 루트 분기를 `index.react.html` 로 일시 변경해야 한다.
- **본 P1-02 결정**: 진입 HTML 일원화는 **P4-07 소관**(`vite.config.ts:9` 근거). P1-02 는 *자산/locales/mimeMap/fallback* 계약만 확정하고, 루트 진입 파일명 정합은 P4-07로 위임함을 명시한다.

## 2. WEB_ROOT 를 dist 로 전환하는 방식 (방식 A)

현재 `WEB_ROOT` 는 `packages/web/` 를 직접 가리킨다 — `dispatch.ts:26-28` 의 fallback `new URL('../../../web/', import.meta.url)`. Vite 산출물은 `packages/web/dist/` 아래 생성된다(실측 §1-2). 따라서:

- **fallback 경로 1줄 변경**: `'../../../web/'` → `'../../../web/dist/'` (`dispatch.ts:28`).
- **packaged 주입 정합**: Electron 메인이 `SPYGLASS_WEB_ROOT = process.resourcesPath/app/web` 를 주입(`server-process.js:121` — `build-infra.md:68` 근거). electron-builder 가 `../web/dist → app/web` 로 복사하면 주입값 무수정 유지(§6, `build-infra.md:263`).
- 효과: `/`·`/assets`·`/locales`·favicon 분기의 **URL 계약은 그대로** 유지된다(단 §1-3 F1, §3 F2 보정 전제).

방식 B(env 모드 스위치 `SPYGLASS_WEB_MODE`)는 dev 분기가 Vite proxy(§5)로 이미 해소되므로 **불필요** — `build-infra.md:197-201`. → **방식 A 채택**.

## 3. /locales publicDir 복사 (F2)

- dispatch `/locales/*` 분기는 `webFile(safePath)` = `WEB_ROOT/locales/*` 를 연다(`dispatch.ts:152-164`, `application/json; charset=utf-8` + `Cache-Control: public, max-age=300`). 로케일 디렉토리 실존: `packages/web/locales/{en,ja,ko,zh}` (실측).
- **실측 확인**: P1-01 `vite build` 산출 `dist/` 에 `locales/` **없음**(NO dist/locales). 또한 `packages/web/public/` 디렉토리 **부재**(실측) — 즉 현재 `vite.config.ts` 에 `publicDir`/복사 플러그인 미설정.
- WEB_ROOT 를 `dist/` 로 옮기면 `dist/locales/` 를 찾게 되어 **모든 로케일 404** → i18n 전면 붕괴.
- **결정(처리안 ①, `build-infra.md:206-209`)**: Vite 가 `packages/web/locales` 를 빌드 시 `dist/locales/` 로 복사하도록 설정. 두 구현 옵션:
  - (a) `vite.config.ts` 에 `publicDir: 'locales'` 지정 시 `locales/*` 가 `dist/` **루트**로 복사되어 `/locales/` 접두가 사라지므로 부적합. → `locales` 를 `public/locales/` 하위로 두고 `publicDir:'public'`, 또는
  - (b) `vite-plugin-static-copy` 로 `locales → dist/locales` 명시 복사(`build-infra.md:207`).
- → **(b) 명시 복사** 권장. dispatch `/locales/*` 분기 **무수정** 유지, electron-builder 도 dist 한 덩어리만 동봉(§6). 실제 적용은 P4-08(§6).

## 4. mimeMap 확장 필요 항목

dispatch `/assets/*` 분기의 mimeMap 은 `js/css/svg/ico` 4종뿐 — `dispatch.ts:139-145`. 그 외 확장자는 `application/octet-stream` 으로 떨어진다(`dispatch.ts:147`). Vite 산출물이 새 확장자를 만들므로 확장 필요.

| 확장자 | mime | 사유 | 즉시성 |
|--------|------|------|--------|
| `map` | `application/json` | sourcemap. `build.sourcemap:true`(`vite.config.ts:41`)로 **이미 산출됨**(`dist/assets/index.react-D7gYVX1f.js.map` 실측) | **필수·즉시** |
| `woff2`/`woff` | `font/woff2`·`font/woff` | 폰트 self-host 전환 시(현재 Google Fonts CDN — `build-infra.md:250`) | 조건부 |
| `png`/`webp` | `image/png`·`image/webp` | 해시 이미지 자산 | 조건부 |
| `json` | `application/json` | 매니페스트 등(단 `/locales/*` 는 별도 분기가 이미 json 처리 — `dispatch.ts:152-164`) | 조건부 |

- `.map` 은 가설이 아니라 **현재 빌드가 실제로 생성**한다(실측). octet-stream으로 서빙되면 브라우저가 sourcemap 로드를 거부할 수 있음 — `build-infra.md:253`.
- mimeMap 확장은 백엔드 무수정 원칙의 **예외**(정적 라우팅 분기 내부)이며 휴먼 검증 포인트(§4-1 D2, `build-infra.md:311` G1).

### 4-1. D2 — 백엔드 "무수정" 경계 명확화 (휴먼 검증 포인트)

미션 전제는 "백엔드 무수정"이다. 그러나 데몬이 클라이언트 자산을 직접 서빙하는 구조상(`dispatch.ts:38` 단일 디스패처) 정적 접합부는 손대야 한다. 경계를 다음과 같이 확정한다:

- **무수정(절대 불변)**: REST API(`/api/*` `dispatch.ts:77-79`), SSE/collect(`/events` `dispatch.ts:69-74`, `/collect` `dispatch.ts:61-66`), 프록시(`/v1/*` `dispatch.ts:56-58`), health(`dispatch.ts:82-96`) — **핸들러 로직 일체 무수정**. apiRouter/sseRouter/handleProxy/eventsCollectHandler 진입 이후는 P1-02 범위 밖.
- **변경 허용(정적 자산 라우팅 분기로 한정)**:
  - `WEB_ROOT` 기준점 (`dispatch.ts:26-28`) → dist 전환 (§2)
  - `/assets/*` 분기의 `mimeMap` 확장 (`dispatch.ts:139-145`) (§4)
  - (페이즈4) 404 직전 SPA fallback 분기 추가 (`dispatch.ts:177-187`) (§5-2)
- 이 경계 해석(특히 mimeMap 확장이 "백엔드 변경"인지 "자산 접합부"인지)은 **휴먼 검증 포인트**로 남긴다 — `build-infra.md:319` 와 동일 결론. dispatch 실제 변경은 web 트랙과 **분리된 커밋 prefix/worktree** 로 격리해 백엔드 회귀와 클라이언트 회귀를 bisect 가 구분하게 한다(tasks.json P1-02 `test_strategy`, review-safety CPL-3).

## 5. dev/운영 모드 통합

### 5-1. dev — Vite proxy (백엔드 무수정)

`vite.config.ts:16` 의 `PROXY_PREFIXES = ['/api','/events','/collect','/v1','/health','/locales']` 는 dispatch 분기와 1:1 정합(`vite.config.ts:14-15` 주석이 dispatch 근거 라인 명시). dev 시 Vite(5173)가 React 앱을 HMR 서빙하고 이 6개 접두를 데몬(9999)으로 위임(`vite.config.ts:18-30,47-50`). `/events` SSE 패스스루는 `ws:false`+스트리밍 비버퍼링으로 보존(`vite.config.ts:25-27`). → dev 에서 데몬은 정적 서빙을 하지 않으므로 stale 자산 사고 없음.

### 5-2. 운영 — 데몬이 dist 서빙 + (페이즈4) SPA fallback

- local daemon/packaged 모두 데몬이 `WEB_ROOT(=dist)` 를 직접 서빙(§2).
- **SPA fallback 부재(F3)**: dispatch 는 `/assets/` 정확 매칭만 서빙하고 미매칭은 404(`dispatch.ts:177-187`). 현재 vanilla main.js 는 해시 라우팅이라 무관하나(`build-infra.md:39`), **React Router v6 도입(페이즈4) 시** `/sessions/:id` 등 직접진입·새로고침이 404가 된다.
- **결정**: 페이즈4(P4-07/관련) 시점에 dispatch 404 직전(`dispatch.ts:177`)에 **"Accept 가 json 이 아닌 GET + 알려진 API/asset 접두 아님 → `index.html` 반환"** 분기 1개 추가 — `build-infra.md:299` G3. P1-02 에서는 **분기 위치·조건만 확정**, 실제 추가는 페이즈4(분리 커밋, §4-1 경계).

## 7. 발견 사항 요약 (실측 기반)

- **F1 (불일치, P4-07 위임)**: 빌드 진입/산출이 `index.react.html` 인데 dispatch 루트는 `index.html` 고정(`dispatch.ts:122`). WEB_ROOT→dist 단독으로는 루트(`/`) 깨짐. 진입 일원화는 P4-07.
- **F2 (불일치, P4-08 처리)**: `vite build` 산출 `dist/` 에 `locales/` 부재 실측, `public/` 디렉토리도 부재 — publicDir/복사 미설정. WEB_ROOT→dist 시 `/locales/*` 전량 404 → 명시 복사 필요(§3).
- **F3 (페이즈4)**: SPA fallback 부재(`dispatch.ts:177-187`). React Router 직접진입 404 위험, 페이즈4 분기 추가.
- **확증**: `base:'/'`+`assetsDir:'assets'` → `/assets/<hash>.js(.map)` 산출이 dispatch `/assets/` 분기와 1:1 정합(실측). `.map` 은 이미 생성되므로 mimeMap `.map` 추가는 즉시 필수.
