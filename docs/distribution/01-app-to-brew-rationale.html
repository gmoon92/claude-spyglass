앱(Electron DMG) 배포 → Homebrew 전환 분석

spyglass의 배포 채널이 "Electron .dmg 앱"에서 "Homebrew Formula"로 옮겨간 배경·근거·현재 상태를 소스 직접 Read로 정리했습니다. 핵심 동기는 Electron 앱의 정식 배포에 드는 Apple Developer Program 연 $99 + 코드 서명/공증 부담을 ad-hoc codesign 기반 무과금 brew 배포로 회피하는 것입니다.

TL;DR

한 줄 요약

"앱 배포" = packages/desktop의 Electron macOS .dmg, "과금" = Apple Developer Program 연 $99(코드 서명·공증).
  • 앱 배포의 정체 — Electron 42.x로 빌드한 macOS .dmg 네이티브 앱.
  • 과금의 정체 — DMG를 정식 배포하려면 Apple Developer ID(연 $99) 코드 서명 + notarization이 필요. 없으면 ① Gatekeeper 차단 ② electron-updater 자동 업데이트 불가.
  • 전환 방향 — standalone Bun bin을 ad-hoc codesign(무료)으로 서명 → tarball → GitHub Release → brew install/upgrade/services로 일원화. Apple Developer ID·연 과금 불필요.
  • 현재 상태 — README·Formula·tap-template·빌드 스크립트로 전환은 확정. 단 release.yml은 tarball 게시까지만 자동화, tap repo 부재로 Formula 자동 갱신 잡은 일시 분리. install-guide.md는 아직 git clone 방식.

Section 1

"앱 배포"의 정체 — Electron DMG

packages/desktop은 Bun 서버 + 웹 대시보드를 macOS 네이티브 셸로 감싼 Electron 데스크톱 앱입니다.

항목근거
Electron 42.x DMG 셸packages/desktop/package.json — electron: ^42.2.0, build:mac → electron-builder --mac dmg
패키징 설정packages/desktop/electron-builder.yml — appId: com.spyglass.desktop, productName: Claude Spyglass, mac.target: dmg (arm64/x64)
동봉 방식bun build --compile standalone bin을 extraResources로 동봉, child로 spawn (server-process.js)
자동 업데이트packages/desktop/src/main/auto-updater.js — GitHub Releases API 폴링 알림
빌드 진입점루트 package.json — desktop:build:mac / desktop:pack:mac
Electron 앱은 30cda7f feat(desktop,brew)(2026-05-25, v2.10.0)에서 "Local agent mode"로 처음 도입됐습니다. 같은 커밋에서 Homebrew "Headless mode"도 함께 구축됐고, 처음부터 brew가 recommended였습니다.

Section 2

"과금"의 정체 — Apple Developer Program 연 $99

Electron DMG를 macOS에 정상적으로 배포하려면 Apple Developer ID 코드 서명이 사실상 필수이고, 이 인증서는 Apple Developer Program 연 $99 유료 멤버십으로만 발급됩니다.

$99

Apple Developer Program

Developer ID 인증서 = 코드 서명·notarization의 전제. 연 단위 유료.

서명 미적용 → Gatekeeper

identity: null. 미서명 DMG는 차단 → 사용자가 xattr -cr 수동 실행 필요.

서명 없으면 자동 업데이트 불가

electron-updater는 Developer ID 필수 → 반자동(수동 DMG 교체)으로 다운그레이드.

auto-updater.js 헤더 주석 (핵심 근거)
"electron-updater 는 macOS 에서 Apple Developer ID 코드 서명이 필수다. 서명을 적용하지 않은 현 상태에서는 무료로 동작하는 반자동 방식을 채택" — GitHub Releases API로 최신 태그 조회 → native dialog 알림 → 사용자가 release 페이지에서 DMG를 직접 받아 교체.

정리 — "앱 배포 시 과금"의 실체

항목미서명 (현재)정식 서명
비용$0Apple Developer Program 연 $99
Gatekeeper차단/경고 → xattr -cr 수동통과
notarization없음필요(Apple 공증 제출)
자동 업데이트반자동(수동 DMG 교체)electron-updater 완전 자동
UX설치 마찰 큼매끄러움

→ "제대로 된 앱 배포 = 연 $99 + 서명/공증 인프라", "미서명 앱 배포 = UX·자동업데이트 희생". 이 딜레마가 brew 전환의 동기입니다.

Section 3

Homebrew 배포가 과금을 회피하는 방식

Homebrew Formula 경로는 Apple Developer ID 없이도 매끄러운 설치·업데이트를 제공합니다.

메커니즘근거효과
ad-hoc codesignscripts/build-release-tarball.sh:125-128 — codesign --sign - --force --options runtimeDeveloper ID 불필요 = 연 과금 0
standalone binspyglass.rb — "standalone bin 안에 Bun 런타임 포함 → depends_on \"bun\" 불필요"시스템 Bun 설치 불필요
tarball + GitHub Releaserelease.yml → build-release-tarball.sh → tar.gz+sha256 업로드호스팅 비용 0
brew servicesspyglass.rb — service do … run [opt_bin/spyglass, serve]launchd 자동시작, 코드서명 무관
brew upgradespyglass.rb — "auto-update 는 brew upgrade 가 canonical"electron-updater 대체
spyglass.rb 헤더 주석 — "코드 서명 / Apple Developer ID 는 미적용. ad-hoc codesign 으로만 서명되어 있음."
# 사용자 설치 흐름 (README.md §Install)
brew tap gmoon92/claude-code-spyglass
brew install spyglass
brew services start spyglass   # 로그인 시 자동 시작
spyglass open
brew upgrade spyglass          # 업데이트

Section 6

brew 배포 완성까지 잔여 작업

현재는 "brew Formula가 소비할 tarball"은 자동 생산되지만, Formula까지 닿는 마지막 연결고리가 끊겨 있습니다.

  1. tap repo 생성 — gmoon92/homebrew-spyglass public repo 생성 후 tap-template/* 푸시 (tap-template/README §1~2).
  2. Formula sha256 충전 — 첫 release 후 macOS 2타겟 sha256을 spyglass.rb에 반영. 미충전 시 brew install 실패.
  3. bump 잡 재도입 — af3c959에서 제거된 bump-homebrew-formula-action을 tap repo 구성 후 release.yml에 복원 → tag push 시 Formula 자동 갱신.
  4. install-guide.md 현행화 — brew tap/brew install/brew services 절을 1차 설치 경로로 추가. 현재 git clone 방식은 "From source(contributors)"로 격하. README와 정합 맞춤.
  5. (선택) desktop 노선 정리 — Electron DMG를 보조 채널로 유지할지/deprecate할지 결정. 유지 시 미서명·xattr 안내를 install-guide에 명시.
