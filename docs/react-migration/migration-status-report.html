HTML producer의 SSoT 정책 충돌 (중요)

판정: render/badges.ts의 배지 함수(toolStatusBadge·agentSpikeBadgeHtml·bloatedSysBadge*·contextSaturationBadgeFullHtml·turnSpikeSummaryHtml)는 React가 약 9곳에서 dangerouslySetInnerHTML로 주입합니다 — 명백한 명령형 잔재입니다. 다만 코드 주석이 "원본 SSoT 문자열 producer를 그대로 호출, 재구현 금지"로 의도적 병존을 명시합니다. 근거는 "서버 컨트랙트(stage/anomaly 필드, ADR-003)·토큰 신뢰도 로직이 자주 변경되므로 vanilla를 단일 oracle로 두고 React는 마크업만 책임진다"입니다. 따라서 배지 React화는 SSoT 이중화 위험이 있어, 순수 판정 로직(색/라벨/단계)을 먼저 단일 모듈로 추출한 뒤 표면만 JSX화하는 신중한 접근이 필요합니다.

Known Imperative Patterns — 의도적 명령형 잔존 (전환 범위 밖)

MetaDocsFlow.tsx의 innerHTML/appendChild 22개: v1이 지적한 항목으로, 본 v3에서 전환 대상에서 의도적으로 제외합니다. SVG flow 다이어그램(노드·엣지·foreignObject 카드)의 명령형 빌드는 "thin React 껍데기 + useRef escape-hatch" 패턴으로, D3류 SVG 직접 조작이 선언적 JSX보다 적합한 정당한 예외입니다. React 공식이 권장하는 escape-hatch이며 SSoT/데이터 흐름을 해치지 않으므로, 마이그레이션 "미완료"가 아니라 설계상 유지 항목으로 분류합니다.

classic i18n 3종 — 정당한 의도적 잔여

커밋 이력(Phase A 8906c96 → B1 225db0e → B2 0d3af1f → 회귀수정 63a1975)상 react-i18next는 이미 초기 언어 SSoT를 가져갔고 reload 없는 반응형 전환이 달성됐습니다. 잔존 이유: index.html의 <option> 4종이 server 회귀 가드(i18n-html-css-drift.test.ts)의 SoT이고, React mount 이전 정적 마크업 + :lang() CSS 캐스케이드 타이밍(FOUC 방지)이며, #react-root 외부 island로 분리되어 clobber를 방지합니다. 제거하려면 <LanguageSwitcher/> 컴포넌트화 + FOUC 처리 + server 테스트 변경(추정 8~12h)이 필요하며, 현재 부채가 아니라 점진 정리 대상입니다.
