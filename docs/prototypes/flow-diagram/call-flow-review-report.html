종합 평가: 이 프로토타입은 통합 준비가 거의 완료된 상태입니다. 프론트엔드는 데모 데이터로 즉시 동작하며, 백엔드 API 구현만 하면 실제 데이터로 전환됩니다. 가장 큰 리스크는 성공/실패 분기를 위한 데이터 모델 부재이나, Phase 1에서 단순화하여 우회하고 Phase 2에서 스키마 확장으로 해결할 수 있습니다.

핵심 결론:

  1. 디자인: 무채색 + accent 포인트 전략은 효과적이나, 접근성(WCAG AA 미달)과 슬롯 그룹화가 P0/P1 수준의 과제입니다.
  2. 데이터: NODES/EDGES 구조는 DB 매핑에 적합하지만, 데이터와 표현의 분리가 필수입니다. 서버는 "무엇인가"만, 클라이언트는 "어떻게 보이는가"만 담당해야 합니다.
  3. 코드: 드래그 인터랙션 버그(null CTM, 터치 미지원)와 renderAll() 전체 재생성 방식이 성능 병목입니다. 즉시 수정이 필요합니다.
  4. 통합: 프론트엔드는 이미 packages/web/assets/에 통합되어 있고, 백엔드 API /api/meta-docs/flow만 구현하면 1~2일 내 MVP 배포가 가능합니다.

1. UI/UX 디자인 검토

1.1 시각적 계층 구조

좌→우 4열(trigger → command → hub → branch/terminal) + 하단 슬롯 행으로 3단계 구분은 명확합니다.

문제: 슬롯 행이 메인 플로우와 수직 거리가 너무 멀어(약 270px), 허브→슬롯의 연결 관계가 시각적으로 단절됩니다. 또한 7개 슬롯 노드가 동일한 Y좌표(600)에 일렬 배치되어 에지가 거의 평행하게 나와 개별 구분이 어렵습니다.

개선안: 슬롯 행을 허브 바로 아래(간격 60~80px)로 이동, 또는 collapsible panel로 변경. 슬롯 노드를 약간의 Y축 오프셋(±10px)으로 교차 배치하여 평행 에지 문제 완화.

1.2 칩 색상 시맨틱

skill(초록), agent(주황), task(주황-빨강), mcp(청록)으로 분류됩니다.

문제: agent(#FF9B6E)와 task(#F77F00)가 모두 주황 계열로 색각 구분이 어렵습니다. slot 노드에서는 분류 칩이 아예 제거되어 아이콘만으로 판단해야 합니다.

개선안: task 색상을 --info 계열(청록 #58A6FF 또는 #22D3EE)로 변경. slot 노드에도 축소된 분류 칩 유지.

1.3 무채색 + accent 포인트 전략

카드/아이콘 박스는 무채색, 중요 흐름 4곳만 accent/success/error로 강조하는 전략은 효과적입니다.

관찰: --flow-grid-dot: rgba(255,255,255,0.045)는 배경 #0a0a0b 위에서 거의 보이지 않습니다(대비율 약 1.05:1). 장식적 텍스처 역할로는 괜찮으나, "격자"라는 명칭과 실제 가시성이 불일치합니다.

1.5 반응형 / 반응성

문제: SVG width="1480" height="780"이 고정되어 있습니다. 줌/팬 기능이 없어 노드가 20개 이상 증가하면 화면 밖으로 나갑니다. 툴팁이 없어 상세 정보 확인이 불가능합니다.

개선안: wheel 이벤트로 줌(0.5x~3x), 스페이스+드래그로 팬. 노드 hover 시 상세 메타데이터 패널 표시(delay 200ms). ResizeObserver로 컨테이너 크기 감지.

1.6 인지 부하

  • 에지 라벨(% 칩)이 노드와 겹칠 수 있습니다(예: h→b 에지가 짧은데 라벨 "100% 분기"가 노드 영역과 충돌).
  • 슬롯 노드 7개의 에지가 모두 bottom→top으로 평행하게 그려져 추적이 어렵습니다.
  • "Outcome"이라는 노드명이 직관적이지 않습니다 — "Branch Point" 또는 "Result"가 더 명확합니다.
  • pill-live의 "live" 텍스트 의미가 불분명합니다.

1.7 디자인 시스템 통합

:root 토큰이 HTML 파일에 하드코딩되어 있어 design-tokens.css와 중복됩니다. flow-diagram.css에는 --color-accent-soft가 정의되지 않았습니다. transition이 120ms cubic-bezier(.2,.8,.2,1)로 하드코딩되어 있습니다.

개선안: HTML의 :root 블록 완전 제거, <link rel="stylesheet" href="design-tokens.css">로 대체. .is-active, .ds-chip 스타일을 각각 flow-diagram.css, chip.css로 이동.

2. 데이터 아키텍처 검토

2.1 NODES/EDGES가 DB 데이터를 잘 표현하는가?

문제: sub 필드가 HTML 문자열('<b>61</b> turns')을 포함 — 데이터와 표현이 혼합됨. x, y, w, h가 노드 데이터에 포함 — 시각적 속성이 비즈니스 모델에 침투. pills: ['hot'], variant: 'hub' 등이 UI 상태 — 서버가 알 필요 없음.

개선안: 데이터/표현 분리

// 서버가 낼 순수 데이터
interface FlowNode {
  id: string;
  type: 'trigger' | 'command' | 'agent' | 'branch' | 'outcome' | 'slot';
  kind: string;
  name: string;
  stats: {
    callCount: number;
    percentage?: number;
    avgToolsPerTurn?: number;
  };
  metadata: Record<string, unknown>;
  groupId?: string;
  parentId?: string;
}

interface FlowEdge {
  id: string;
  from: string;
  to: string;
  type: 'flow' | 'slot' | 'outcome';
  stats: { count: number; percentage: number };
  outcome?: 'success' | 'failure';
}

클라이언트는 type + kind를 받아 icon, chip, variant, sub 텍스트로 매핑합니다.

2.2 확장성

강점: kind가 자유 문자열이어서 새 분류 추가가 쉬움.
약점: variant enum에 새 타입 추가 시 클라이언트/서버 양쪽 수정 필요.

개선안: type은 제한된 enum으로 두고(노드 역할), kind는 완전 개방형 문자열로 유지. metadata 객체로 확장 필드 격리.

3. 코드 품질 검토

3.1 SVG + foreignObject 크로스 브라우저 이슈 P1

문제: Safari에서 foreignObject 내부 HTML 요소가 제대로 렌더링되지 않거나 크기가 0으로 계산될 수 있습니다. overflow 속성이 명시되지 않았습니다.

개선: fo.setAttribute('overflow', 'visible') 추가. card에 position: relative; width: 100%; height: 100% 추가.

3.2 드래그 인터랙션 버그 P0

버그위치시나리오
CTM null 오류 svgPoint() 733-738 SVG가 display: none이거나 DOM에 없을 때 getScreenCTM()이 null 반환
터치 미지원 bindDrag() 746-786 모바일/터치스크린에서 드래그 불가
DOM 재배치 오버헤드 nodesLayer.appendChild() 765 드래그 시작 시마다 DOM 재배치로 성능 저하

즉시 수정: svgPoint()에 null 체크, 터치 이벤트 지원, DOM 재배치 대신 CSS z-index 사용.

3.3 renderAll() 성능 P0

문제: 전체 DOM을 innerHTML = ''로 지우고 모든 노드/에지를 처음부터 재생성. 노드 100개, 에지 200개 시 300개 DOM 요소 생성. 실시간 데이터 갱신 시 전체 화면 깜빡임.

개선: 변경 감지 기반 부분 업데이트. 기존 DOM 재사용, 삭제된 것만 정리. DocumentFragment 사용.

3.4 베지어 곡선 정확성 P1

  • 최소 거리 40px 고정으로 짧은 거리에서 시각적 왜곡 발생.
  • anchorPoint가 노드 중앙에서 시작 — 에지가 노드 내부를 관통하는 것처럼 보임.
  • 라벨 위치가 t=0.5 고정 — 곡률 큰 경우 시각적 중간점과 불일치.

개선: padding: 4px 적용. 상대적 거리(dist * 0.4) 사용. 곡률 기반 라벨 위치 조정.

3.5 메모리 누수 P1

  • 이벤트 리스너 등록 후 제거 메커니즘 없음 — renderAll() 반복 호출 시 누적.
  • nodeIndex.clear()만으로 이전 foEl 참조 해제 불완전.
  • innerHTML 사용으로 파싱 오버헤드.

개선: addManagedListener() / cleanupListeners() 패턴 적용. DOM 참조 명시적 해제.
